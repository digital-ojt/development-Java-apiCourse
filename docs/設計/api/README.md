## 🔧 API 設計方針

### 基本原則

- **RESTful 設計**: HTTP メソッド（GET, POST, PUT, DELETE）を適切に使用
- **統一性**: 全 API で一貫したレスポンス形式とエラーハンドリング
- **セキュリティ**: JWT 認証による安全な API アクセス制御
- **拡張性**: 外部システム連携に対応可能な設計

### 認証・認可

- **認証方式**: JWT（JSON Web Token）
- **認可制御**: 管理者権限による操作制限
- **セッション管理**: ステートレス設計

## 📊 API カテゴリ詳細

### 🔐 共通 (`共通/`)

システム全体で共通利用される API 仕様と認証機能

#### API システム概要.md

- **目的**: API システム全体のアーキテクチャ設計
- **内容**: 技術仕様、システム構成、セキュリティ要件

#### API 仕様(共通).md

- **目的**: 全 API 共通の設計規約
- **内容**: レスポンス形式、エラーコード、ヘッダー仕様

#### 認証 API.md

- **目的**: 認証・認可機能の API 仕様
- **内容**: ログイン、トークン管理、権限制御

### 📦 部品在庫管理 (`部品在庫管理/`)

部品の入荷・在庫照会に関する API 群

#### 部品入荷 API.md

- **エンドポイント**: `/api/v1/parts/receive`
- **機能**: 部品入荷処理、在庫更新、履歴記録
- **外部連携**: 購買システムとの連携

#### 部品在庫照会 API.md

- **エンドポイント**: `/api/v1/parts/stock`
- **機能**: 部品在庫情報の検索・照会
- **検索条件**: カテゴリ、センター、在庫量範囲

### 🏭 製品在庫管理 (`製品在庫管理/`)

> ⚠️ **開発予定**: 製品在庫管理 API は今後実装予定です

**予定機能**:

- 製造入庫 API（部品 → 製品変換）
- 製品出荷 API（販売システム連携）
- 製品在庫照会 API（在庫状況確認）

## 🚀 利用方法

### 開発者向け

1. **共通仕様の理解**

   ```
   1. APIシステム概要.md → システム全体理解
   2. API仕様(共通).md → 共通規約の確認
   3. 認証API.md → 認証方式の実装
   ```

2. **個別 API 開発**
   ```
   1. 各APIのmd ファイルで詳細仕様を確認
   2. リクエスト/レスポンス形式に従って実装
   3. エラーハンドリングを共通仕様に合わせて実装
   ```

### API 利用者向け

1. **認証トークン取得** → `認証API.md` 参照
2. **必要な API 仕様確認** → 各カテゴリの md ファイル参照
3. **共通エラー対応** → `API仕様(共通).md` 参照
